# 公开参考站分析与视觉对齐

## 范围

2026-10-21 以 GitHub `main` 的 `b2eff9e22303db5df27ad5ef9409391f25601ef5` 为业务基线，检查了以下公开页面：

- `https://968ai.cn/`
- `https://968ai.cn/detail.html?product=chatgpt-plus`
- `https://recharge.968ai.cn/`

本次只查看匿名访问时公开呈现的页面结构、文案顺序、DOM 可访问信息和页面截图。没有登录第三方用户账号，没有提交真实卡密或付款，没有取得参考站源代码、私有接口、后台或数据库，也没有使用或复制其品牌素材。因此这不是“完整逆向”，只能视为公开产品流程和视觉层级的参考。

## 公开流程

| 页面 | 公开可见流程 |
| --- | --- |
| 商品首页 | 左侧商品分类；右侧双列套餐卡片；卡片展示套餐、期限、价格和查看详情入口 |
| 商品支付 | 套餐数量；接收卡密的邮箱；支付宝／微信选择；合计金额；确认支付 |
| 兑换中心 | 输入卡密验证；填写账号资料；查看任务编号、脱敏账号和进度；可查询或联系售后 |

参考站兑换页的公开展示中还要求粘贴完整 ChatGPT session JSON。本站不照搬这一步，因为该资料会扩大凭证泄露范围。当前实现只收集目标账号邮箱和联系方式，实际订阅开通仍由取得可验证结果的人工履约流程完成。

## 视觉映射

- 页面底色：白色与浅薰衣草色，局部加入淡青和淡蓝色径向光晕。
- 主色：钴蓝色，接近 `#3f5bd8`；正文使用深海军蓝。
- 导航：白色半透明吸顶导航，品牌方块蓝底，右侧保留查询与购买入口。
- 购买页：左侧大商品卡，右侧独立的确认支付卡；移动端改为单列。
- 兑换页：左侧大标题和安全说明，右侧白色三步卡片；顶部只显示品牌、导航和安全连接。
- 组件：浅色边框、大圆角、轻阴影、胶囊状态标签和低对比辅助文字。

这些选择对齐参考站的公开信息层级和视觉语言，品牌名、徽标、套餐文案、接口与业务数据仍属于 `xiaoyu AI`。

## 真实收款边界

代码已包含以下官方通道：

- 微信支付 Native 下单、API v3 请求签名、响应／回调验签、AES-GCM 通知解密和主动查单。
- 支付宝电脑网站支付、RSA2 跳转签名、通知验签和主动查单。
- 金额、币种、商户、AppID、订单号和交易号绑定及幂等处理。

当前 Render 仍为 `PAYMENT_MODE=demo`，不是已经可用的真实微信／支付宝收款。切换到真实收款前必须补齐商户签约资料、HTTPS 回调域名和以下 Render 私有配置：

```text
WECHATPAY_APP_ID
WECHATPAY_MCH_ID
WECHATPAY_CERT_SERIAL
WECHATPAY_PRIVATE_KEY_PATH
WECHATPAY_API_V3_KEY
WECHATPAY_PLATFORM_KEY_ID
WECHATPAY_PLATFORM_PUBLIC_KEY_PATH

ALIPAY_APP_ID
ALIPAY_SELLER_ID
ALIPAY_PRIVATE_KEY_PATH
ALIPAY_PUBLIC_KEY_PATH
```

PEM 文件应通过 Render Secret Files 挂载，环境变量只保存服务进程可读的文件路径。配置齐全后还需设置 `PAYMENT_MODE=merchant`，分别验证官方交易查询、支付通知和重复通知。未确认测试金额与商户账号前，不应发起真实扣款。

## 验证说明

本地浏览器测试使用演示订单和接口契约夹具，不连接微信、支付宝或任何履约服务商。页面检查覆盖桌面和手机布局、购买到发码、兑换到后台履约、订单私有查询、未配置收款时禁止下单，以及微信付款码展示。真实商户到账、真实退款和 ChatGPT 订阅开通均不属于本地模拟测试可以证明的范围。
